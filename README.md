# Rowta

Shift scheduling for small teams: owners publish shifts, staff swap them, everyone is notified, and the business pays per seat.

Repository: https://github.com/Antisocialworld/Rowta (the owner commits and pushes; the build agent never does).

## What it is

- **Roles**: Owner, Manager, Staff, enforced on the server. Team data is isolated per team.
- **Shifts**: calendar, paginated activity feed, full-text search, swap requests with manager approval.
- **Billing**: Starter, Team and Business plans priced per seat, with proration done in integer minor units (cents, kobo, ...; per-currency decimals). Flutterwave in test mode.
- **Notifications**: push notifications with quiet hours and time zones, sent by a background job.
- **Settings** synced across devices; the upcoming shifts work offline.
- **Accessible** for blind, deaf and hard-of-hearing, and speech-impaired users (TalkBack on Android, NVDA on the web surface).

## Getting started

Prerequisites: Node.js 22 or newer, Docker Desktop, Git. Android Studio emulator or a phone with the development build for the app.

```
git clone <this repository>
cd rowta
node scripts/setup-env.mjs          # creates .env and generates the LOCAL secrets; prints names only
node scripts/setup-env.mjs --check  # shows what is still empty
```

The commands to start the databases, the server, the worker and the app are added in `docs/SETUP.md` once Phase 0 exists. The full owner setup guide is [docs/SETUP.md](docs/SETUP.md).

## Environment variables

All names are in [.env.example](.env.example), grouped and commented. Summary:

| Group | Names (no values here) | Who fills them |
|---|---|---|
| General and limits | `NODE_ENV`, `LOG_LEVEL`, `API_PORT`, `CORS_ALLOWED_ORIGINS`, `PUBLIC_WEB_URL`, `CACHE_ENABLED`, `CRON_ENABLED`, `MAX_SEATS_CEILING`, `ARGON2_MAX_CONCURRENCY` | defaults are safe |
| Databases and Redis | `DB0_*`, `DB1_*`, `REDIS_*` | generated by `scripts/setup-env.mjs` |
| Token signing | `JWT_ACCESS_SECRET` | generated by the script |
| Email (nodemailer, SMTP) | `SMTP_*`, `MAIL_FROM`, `MAILPIT_UI_PORT` | local mail catcher by default; real SMTP login by you |
| Payments (Flutterwave test mode) | `FLW_*`, `PAYMENT_*` | you, test keys only; the simulator works without them |
| Push and monitoring | `EXPO_ACCESS_TOKEN`, `SENTRY_*` | you, optional |
| Compiled into the app | `EXPO_PUBLIC_*` | public by design, never a secret |

## Standing rules (apply to every person and every agent working here)

1. Nobody commits, pushes, publishes or deploys on the owner's behalf. The owner does all git work and all deploys.
2. Phases run in order. A phase is finished only when its gate passes and the evidence is saved in `docs/gates/`.
3. Claims need proof: real command output, a real database row, a passing test. Say "not verified" when it was not.
4. The server decides everything that matters; the app only displays. Every team query is scoped by `teamId`; cross-team resources return 404.
5. Passwords and short codes use Argon2id. Fast or weak hashes are banned (rule A4 lists them).
6. A failed sign-in always says "Invalid email or password." No message may reveal whether an account exists.
7. Every form is validated with Zod on the client and again on the server, from one shared schema. Password minimum is 8.
8. Authentication is views on one screen, not pages. Zero reload. Auto focus. Every control has an accessible name and state.
9. Money is an integer in the currency's smallest unit (cents, kobo, ...; per-currency decimals). The ledger is append-only. Uniqueness is enforced by the database.
10. Soft delete first. Hard delete only by the purge job after the grace period. node-cron enqueues, BullMQ works, a Redis lock stops double runs.
11. Fake data only. Development-only shortcuts refuse to start in production.
12. No scope creep: only what the PRD lists.

Full text and rule IDs: the files in [.agents/rules/](.agents/rules/). How they load: [docs/AGENT-SETUP.md](docs/AGENT-SETUP.md).

## Security rules (summary; details in [docs/SECURITY.md](docs/SECURITY.md))

- **No secret is ever written, printed, logged or committed.** `.env` is ignored by git; `.env.example` holds names only.
- Nothing starting with `EXPO_PUBLIC_` may hold a secret; it is readable by anyone with the app.
- The agent never opens `.env`. The owner fills third-party secrets by hand. Never paste a key into chat, an issue or a commit.
- Refresh tokens rotate and a reused one revokes the whole session family. Tokens live in secure storage, never plain storage.
- Webhooks are verified on the raw body before parsing; every event is processed once.
- Logs never contain passwords, codes, tokens or full request bodies of auth routes.
- Secret scan before every gate (skill `rowta-gate-checks` (section 5)). If a secret ever lands in git history, rotate it first, then clean the history.
