# Security

State: skeleton. Each section is filled with evidence as its phase is completed. Nothing here claims a control exists until a gate shows it.

## 1. Secret handling (in force from day one)

- `.env` is never committed (`.gitignore` ignores `.env` and `.env.*`, keeps `.env.example`). `.env.example` holds names only.
- Local secrets are generated by `scripts/setup-env.mjs`, which prints names, never values. Third-party secrets are pasted by the owner.
- The coding agent never opens `.env` or `.env.*` other than `.env.example`, never prints a secret, and masks any sensitive value.
- Secret scan before every gate (skill `rowta-gate-checks` (section 5)). Reports file and line only.
- If a secret is ever exposed: rotate it at the provider first, then remove it from history.

## 2. Values compiled into the app (`EXPO_PUBLIC_*`), each safe because it is public by design

| Name | Why it is safe |
|---|---|
| `EXPO_PUBLIC_API_URL` | an address, not a credential |
| `EXPO_PUBLIC_SENTRY_DSN` | a Sentry DSN only allows sending events |
| `EXPO_PUBLIC_EAS_PROJECT_ID` | an identifier, not a credential |
